# Codex adapter

The initial adapter uses Codex's documented `PermissionRequest` lifecycle hook.
It displays the tool description and complete JSON input, then offers the two
decisions the hook API can currently return safely: Allow and Deny.

## Configure

1. Start `keycap-host`.
2. Merge `hooks.fragment.json` into `~/.codex/hooks.json` and replace the
   absolute-path placeholder.
3. Open `/hooks` in Codex and explicitly review/trust the new hook.

If the broker is unavailable, the hook emits no decision and Codex presents
its normal terminal approval prompt.

Choose **Handle in Codex** in the overlay or press Escape to dismiss the active
request without making a selection. The hook emits no decision, returning the
approval to Codex's terminal UI.

## Rich adapter

`app_server_bridge.py` is a transparent stdio proxy for clients that normally
launch `codex app-server`. Configure the client to launch:

```sh
python3 /ABSOLUTE/PATH/TO/adapters/codex/app_server_bridge.py codex app-server
```

The proxy routes command and file approvals—including `acceptForSession`—and
`item/tool/requestUserInput` through Keycap. If the user chooses **Handle in
Codex**, the original server request is forwarded to the parent client so its
normal UI remains authoritative. Secret and free-form questions also pass
through unchanged.

The bridge uses the App Server schema generated by the installed Codex version;
WebSocket transport remains experimental upstream and is intentionally outside
this stdio proxy.

The hook does not invent an Always Allow option because Codex currently rejects
permission updates from `PermissionRequest` hooks.
